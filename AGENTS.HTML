Berry Claw 产品对齐文档

本文件是 Berry Claw 的产品、架构、开发和发布事实源。README.md 和 AGENTS.md 只引用本文档，避免文档漂移。

定位

Berry Claw 是基于 Berry Agent SDK 的产品。它不是 SDK 本体，而是把 SDK 能力包装成可运行的后端实例、Web 前台、桌面客户端和手机客户端。

后台
@berry-agent/claw-server：host adapter、CLI、REST/WebSocket、实例密钥、产品配置、SDK runtime 挂载。
前台
@berry-agent/claw-client：桌面/Web 产品 UI；渲染 SDK session view、facts、approval、files、browser，不拥有 agent state。
平台壳
claw-desktop 提供 Electron 原生能力；claw-mobile 应做移动专用 UI，复用协议和 runtime，不原样塞桌面三栏。

重构北极星：Claw 是 Host，不是 Harness

Claw 的长期目标不是继续扩张成“另一个 SDK”。它应该站在 Anthropic managed-agent 图里的 Orchestration/Host 位置：选择运行位置、连接用户、注册能力、展示状态；agent turn、session、tool loop、approval 语义必须回到 SDK runtime。

Client / Shell

  • chat UI
  • approval UI
  • file/browser/session panels
  • human annotation draft
  • desktop native browser view

SDK Managed Runtime

  • session/event/message facts
  • run / pause / resume / wake
  • context builder + provider call
  • tool loop + safety + approval event
  • hands/MCP/sandbox lifecycle

Claw Server Host

  • auth and connection
  • product config
  • agent root selection
  • REST/WS bridge
  • credential UI + scoped vault

产品 UI + SDK ApprovalBroker + SDK event log：Claw 不保存 pending map，request/decision 已写入 SDK session events。

SDK ManagedAgentRuntime + session view + Claw FactBus：历史、active session、chat turn glue、context size 从 SDK 派生。

Built-in tools
Claw berry-tools 已收窄：只剩 read-only berry_status / berry_config_get host introspection。
管理 API 走 host control plane；真正给 agent 的 hands 走 SDK capability registry。
Contracts
Claw contracts 已复用 SDK content、chat/session、AgentHome、ProjectSharedPaths、team/worklist schema，并定义 config/models/prompt-packs/prompt-blocks/sessions/credentials/skills/safety REST envelope 和 WebSocket command schema。
SDK 导出 domain schema；Claw contracts 只定义 transport envelope、产品 AgentEntry 和 UI-only facts。
Team host
TeamHost 承担 SDK Team 到产品 AgentEntry 的桥接；冷启动加载通过 AgentManager.ensureTeamsLoaded() / resolveTeamForAgent()，route 层不再知道 rehydrate 细节。
SDK Team 继续拥有 team/worklist/message/disband；Claw 只做 host-side agent registry 映射和 facts。
Host adapters
AgentSessionHost / AgentContextHost / AgentFileHost / AgentChatHost / AgentMcpHost / AgentReloadHost / AgentLifecycleHost 从 AgentManager 拆出 SDK session、approval event、memory、project knowledge、prompt block、只读 file browser、chat turn、MCP attach/release、runtime rebuild/reload 和 restart 访问。
AgentManager 保持 facade/cache/facts 协调；SDK 仍拥有 session/event/context/file-browser/runtime 语义。
Server routes
server.ts 已降为 composition root；auth/config/agent/facts/safety/skills/MCP/team/session/system 等 REST API 拆到 routes/*，SDK-agent detail 访问集中在 sdk-agent-routes.ts。
入口只负责 manager/auth/app 组装、路由注册、静态资源和 HTTP 启动。
WS chat stream
ws/chat-handler.ts + ws/server.ts 分别负责 SDK AgentEvent 投影和 WS 建连/FactBus 广播/控制消息；server.ts 不再夹带长实现。
Safety approval 只拿 broadcast 函数，SDK safe 继续拥有 approval lifecycle。
Product config
config-schema.ts + ClawHome 分别拥有产品 config schema/normalization 和产品目录布局；ConfigManager 只保留公共配置 API。
Claw 只拥有产品配置和路径选择，不把 SDK agent home 内部结构复制到产品层。

跨端策略

DesktopElectron shell + native browser view + filesystem affordances。可承载最完整的 workspace 面板。
Web远程连接后台实例；浏览器能力受 Web sandbox 限制，不能假装拥有桌面级 native browser。
Mobile移动专用 UI：线程、审批、diff、文件预览、截图/注解、运行状态。复用 contracts/runtime，不复用桌面三栏布局。
Server长期进程和 host control plane；不保存第二份 agent 数据，不把 session 做成产品数据库。

前端边界

  • App.tsx 只负责实例连接、全局 view 切换、runtime store 编排和顶层布局；不再内联导航 chrome、右侧工作区、复合输入框或项目详情页面。
  • app/AppNavigation 拥有桌面侧栏和移动顶部导航；inbox/InboxView 只编排聊天工作区，agent/session 选择器、空态、context meter、inference details 拆成独立 inbox 组件。
  • WorkspaceRail 是按需 lazy chunk，只负责右侧栏布局和 tab 分发；workspace/BrowserRail、workspace/FilesRail、workspace/SessionRailContent 分别拥有桌面浏览器注解、只读文件浏览、session history/todo 展示。
  • ChatInput 拥有人类复合草稿：text、image、annotation、队列、interject、reasoning/model 控件；未发送草稿不进入 SDK session。
  • MessageBubble 只负责单条消息壳、用户输入块和 inference disclosure；turn activity、timeline、tool folding 在 message/TurnActivity，Markdown lazy wrapper 在 message/AssistantMarkdownView。
  • AgentsPage 只负责选中 agent、读取 facts 和调用 host control plane；agent 列表、身份面板、编辑器、portrait/helper、装备槽模块在 agents/*。
  • ProjectsPage 只展示 project 聚合、SDK projectSharedPaths 和项目级 safety 控制；项目聚合 hook 在 projects/summary，页面本身 lazy-load。
  • settings/* 拥有连接、主题、凭证、provider、model、tier、safety、共享表单控件和 model-catalog event；components/mcp/McpServerRow 是 MCP row 的共享渲染事实源；SettingsPage 只是小型 composition shell，并用 lazy tab chunk 避免一次加载完整设置 UI。

安装和启动

npm install -g @berry-agent/claw-server@alpha
berry-claw start
berry-claw key show

后台默认监听 http://localhost:3210。手机/桌面/浏览器前台必须能访问该地址；手机上的 localhost 指手机自己，不是电脑。公网、局域网 IP、VPN/Tailscale、Tunnel 都可以作为连接方式。

SDK 边界

  • Claw 不重复实现 SDK runtime：agent lifecycle、provider messages、session view hydrate、event log、tool loop、MCP adapter、Skill loader、PromptPack、memory、safe、observe collector、context-window inference、execution environment contract 和 environment prompt 属于 SDK。
  • Claw 负责产品事实和交互：server instance、auth、UI state、facts bus、REST/WebSocket、平台壳、配置页面。
  • 删除产品 AgentEntry 只删除 registry row；Claw 不移动、不归档、不删除 SDK-owned agent home。后续如果需要清理数据，应由 SDK 提供显式 data lifecycle API。
  • 丢弃或关闭 live runtime 必须先调用 SDK ManagedAgentRuntime.destroy()；Claw 可以释放产品侧引用和 MCP 投影，但 hand、memory provider、sleep/interject waiter 的关闭语义属于 SDK。
  • 项目共享数据路径属于 SDK：Claw server 只把 projectSharedPaths 投影进 facts，Claw contracts 复用 SDK schema，Claw client 只显示后端给出的路径。
  • 项目级 safety 配置属于 SDK safe：Claw 可以编辑 level，但读写 .berry/safety.json 的语义不在产品层复制。
  • 人类输入块、AgentHome、ProjectSharedPaths schema 来自 SDK @berry-agent/core/schema；chat/session view schema 来自 SDK @berry-agent/core/chat-schema；team/worklist schema 来自 SDK @berry-agent/team；Claw contracts 只给 WebSocket/REST 包 transport envelope。
  • 配置、模型目录、PromptPack、prompt block、session list/detail、credential、skill market、team 和 safety snapshot 的 REST payload shape 属于 @berry-agent/claw-contracts；对应 request body 和 WebSocket command 也应使用 contracts schema 校验，client 不再 mirror server payload interface，server 测试必须用 contracts schema 校验实际响应。
  • 产品 AgentEntry shape 属于 @berry-agent/claw-contracts，并由 ConfigManager 严格校验；运行时 lifecycle 字段不能进入产品 config。
  • team 能力通过 SDK Hand 挂载；Claw 不再逐个注册 team tool。
  • team runtime/product adapter 属于 Claw TeamHost；SDK Team 仍是团队状态和 artifact lifecycle 的唯一语义来源。
  • HITL pending approval 生命周期属于 SDK safe ApprovalBroker；Claw server 只广播问题和接收 human decision，不维护第二个 pending map。
  • approval request/decision 已写入 SDK events.jsonl；Claw 只把 broker 快照转交给 SDK appendSessionEvent。
  • session facts 已进入统一 FactBus；创建、加载、聊天完成和删除会话都从 SDK AgentSessionView 派生事实。
  • MCP server 生命周期属于 SDK @berry-agent/mcp 的 MCPManager / MCPToolCenter；Claw server 只提供三层配置路径、REST 操作和 facts 投影。enable/disable/restart 后，Claw 以 MCPManager.getHandsForAgent() 为事实源同步 live runtime 的 MCP Hands，不保留第二套 MCP tool 状态；MCP 批量断连的清理/报错语义属于 SDK。
  • MCP 标准文件名、默认 Playwright MCP 模板、默认配置写入、raw config shape validation 和内置 MCP package normalization 来自 SDK @berry-agent/mcp；Claw 不维护第二份 mcp-constants、npx 解析、MCP schema 校验或默认文件写入逻辑。
  • 本地 workspace tool hand 由 SDK @berry-agent/tools-common 的 createLocalWorkspaceHand 组装；OS sandbox 是 SDK ExecutionEnvironmentProvider 的一种实现，Claw 只选择 workspace/project、credential、allow-list 和未来的容器/远程 runner provider。
  • shell、sandbox shell 和 MCP stdio 的默认 command env 来自 SDK createCommandEnvironment()；Claw 不应把 provider/API credentials 通过全局 process.env 透传给 agent runner，需要时必须显式 scoped 注入。
  • Claw inspect、facts 和 UI 只能看到 SDK ProviderPublicConfig；真实 provider apiKey 不应出现在 runtime snapshot、REST response 或 WebSocket facts 中。
  • Claw agent model 只保存 tier:X、model:X 或 bare model id；自定义 provider 的 type/baseUrl/apiKey 只能在 config Layer-1 ProviderInstance 中维护，不能用 raw: model string 绕过 SDK models registry。
  • auto safety classifier 和 managed guard pipeline 属于 SDK safe；Claw 只负责在 Settings 中显示、启用/禁用、覆写模型，并把配置持久化到 ~/.berry-claw/config.json。
  • agent memory / project knowledge 文件只能通过 SDK Agent API 读写；Claw 不在 cold agent 分支里直接读取 MEMORY.md 或项目 AGENTS.md。
  • prompt block 编辑和 teammate instructions 写入都通过 SDK Agent.read/writeInstructions 与 writeProjectKnowledge；Claw 不直接写 agent workspace 文件。
  • team rehydrate 判断通过 SDK team 的 readTeamLeaderId(project) 完成；Claw 不直接解析 .berry/team.json。
  • team disband 通过 SDK Team.disband() 删除团队/worklist artifacts；Claw 只移除产品侧 teammate AgentEntry。
  • 聊天历史通过 SDK getSessionView/listSessionViews 从 events.jsonl 构造；event log 读写由 SDK zSessionEvent 校验，实时 timeline 通过 SDK timelineEventFromAgentEvent 投影；不能从 compact 后的 messages.json 还原产品历史，也不能在 Claw 后端保存第二份消息状态。
  • session/chat lifecycle 和 context size 通过 SDK ManagedAgentRuntime 执行；Claw 不维护 active-session map，也不自己拼 pending user / assistant hydrate 或读取 session token metadata。
  • Claw 的 live agent runtime 组装已上移到 SDK @berry-agent/runtime；Claw AgentRuntimeFactory 只是产品配置适配器，AgentManager 现阶段用 SDK ManagedRuntimeRegistry 管 live runtime mount/drop/replace，并 await teardown，不再直接拼 provider、hands、memory、safe、observe、skills。SDK 已提供 ManagedRuntimeSupervisor / ManagedRuntimeWakeScheduler 作为下一步运行所有权和后台唤醒边界，Claw 不应再新增自己的 lease/wake/job 状态机。
  • Claw 为每个 agent 选择的 sandbox/container/remote execution environment 交给 SDK ExecutionEnvironmentProvider 供给，并由 SDK runtime lifecycle/registry 持有；runtime reload/delete/close 时 await ManagedAgentRuntime.destroy()，确保 hand、memory provider 和环境释放完成后才继续，后续容器/远程 worker 也按这个边界接入。
  • AgentSessionHost 负责 SDK session view/fact/delete/todo 和 approval request/decision event 持久化；AgentContextHost 负责 SDK memory/project knowledge/prompt block API；AgentFileHost 负责只读 file browser。
  • AgentChatHost 负责 live turn dispatch 和 observe cost enrichment；AgentMcpHost 负责 per-agent MCP hand sync/release；AgentReloadHost 负责 runtime rebuild/reload/model switching；AgentLifecycleHost 负责 restart/reload runtime。
  • config-schema.ts 是产品 config schema/normalization 事实源；ClawHome 是产品目录布局事实源。ConfigManager 不再同时承载 schema、路径和业务配置变更。
  • claw-desktop 的 native Chromium browser hosting 在 browser-surface.cjs；client URL resolution 在 client-url.cjs；SDK 不接触 Electron BrowserView/WebContentsView。
  • server.ts 是 composition root：REST handlers 拆到 routes/*，WS 建连和控制消息拆到 ws/server.ts，chat stream 投影拆到 ws/chat-handler.ts。
  • WebSocket chat streaming 通过 ws/chat-handler.ts 投影 SDK events；server.ts 不承载长 stream switch 逻辑。
  • 新建和恢复 session 走 REST + SDK AgentSessionView；WebSocket 不再有 new_session、resume_session、session_created、session_resumed 旧事件。
  • agent 激活和模型切换走 REST control plane；WebSocket 不再有 switch_agent、switch_model、agent_switched、model_switched 旧事件。
  • berry_status 和 berry_config_get 是只读 host introspection；配置写入、tier/model 修改、restart 属于 REST/UI host control plane，不作为 agent tool 暴露。

代码规范

  • 不引入无事实源缓存；本地 UI 状态必须能从后端 facts/events 恢复。
  • 魔法值集中维护，避免散落在组件和 server handler。
  • 前后端协议以 @berry-agent/claw-contracts 为事实源，不能各写一份 schema。
  • 涉及旧 schema、旧字段、旧兼容路径时直接删除，当前 alpha 阶段不背兼容成本。
  • 发布前至少运行 npm run build、npm test、平台构建或 GitHub Actions release workflow。
