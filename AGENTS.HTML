Berry Claw 产品对齐文档

本文件是 Berry Claw 的产品、架构、开发和发布事实源。README.md 和 AGENTS.md 只引用本文档，避免文档漂移。

定位

Berry Claw 是基于 Berry Agent SDK 的产品。它不是 SDK 本体，而是把 SDK 能力包装成可运行的后端实例、Web 前台、桌面客户端和手机客户端。

后台
@berry-agent/claw-server：Node server、CLI、REST/WebSocket、实例密钥、配置管理、内置 Web UI。
前台
@berry-agent/claw-client：同一份 React/Vite UI，被浏览器、Electron、Capacitor 复用。
平台壳
claw-desktop 打 macOS/Windows/Linux；claw-mobile 打 Android/iOS。

安装和启动

npm install -g @berry-agent/claw-server@alpha
berry-claw start
berry-claw key show

后台默认监听 http://localhost:3210。手机/桌面/浏览器前台必须能访问该地址；手机上的 localhost 指手机自己，不是电脑。公网、局域网 IP、VPN/Tailscale、Tunnel 都可以作为连接方式。

发布

  • npm 公开包：@berry-agent/claw-server、@berry-agent/claw-contracts。
  • GitHub Release 资产：npm tarball、macOS zip/dmg、Windows exe/zip、Linux AppImage、Android APK。
  • 每次发版本使用同一个版本号，当前快速迭代阶段不维护旧数据兼容。

SDK 边界

  • Claw 不重复实现 SDK runtime：agent lifecycle、provider messages、event log、tool loop、MCP adapter、Skill loader、PromptPack、memory、safe 属于 SDK。
  • Claw 负责产品事实和交互：server instance、auth、UI state、facts bus、REST/WebSocket、平台壳、配置页面。
  • 聊天历史只能从 events.jsonl 构造 timeline；不能从 compact 后的 messages.json 还原产品历史。

代码规范

  • 不引入无事实源缓存；本地 UI 状态必须能从后端 facts/events 恢复。
  • 魔法值集中维护，避免散落在组件和 server handler。
  • 前后端协议以 @berry-agent/claw-contracts 为事实源，不能各写一份 schema。
  • 涉及旧 schema、旧字段、旧兼容路径时直接删除，当前 alpha 阶段不背兼容成本。
  • 发布前至少运行 npm run build、npm test、平台构建或 GitHub Actions release workflow。
